# Today 下一阶段产品方案

状态：方案已确认，进入发布候选验证（真实 7 天试用和生产证据仍待完成）

版本：2026-11-08

## 1. 目标

在现有“记录—理解—行动—回看”核心闭环上，解决四个问题：

1. 能否用真实用户数据判断用户是否持续使用，而不是只看功能是否可用。
2. 能否让用户更低成本地记录，并在 Chat 中把对话整理成可确认的今日记录。
3. 能否让用户明确控制哪些记忆会被 Today 使用。
4. 能否满足试用、隐私和发布前的基本要求。

本阶段的成功标准是形成一个可测量、可授权、可发布候选版本，而不是继续扩展宠物玩法或第三方集成。

## 2. 交付范围与优先级

### P0：真实用户 7 天验证与指标看板

对象：5～10 位受邀用户，先 Android，必要时补 Web。

核心任务：

- 定义激活事件：注册完成、首次记录保存、首次 Chat 消息、首次查看总结、首次确认建议。
- 定义留存：次日、3 日、7 日回访；回访必须是打开应用并完成有效行为之一。
- 定义北极星指标：7 天内至少完成 3 次有效记录且确认至少 1 个 AI 总结或行动建议的用户数。
- 建立内部看板，按用户、日期、版本、平台查看漏斗和失败原因。
- 每位测试用户只使用测试账号；收集定量数据和一次性反馈，不把原始私密文本直接展示给运营人员。

验收：能从事件表重算注册漏斗、首条记录完成率、建议确认率、行动完成率、D1/D3/D7 留存，并能区分事件缺失与用户未使用。

### P0：语音记录与 Chat 生成记录

第一版只做“按住说话/点击录音 → 转写 → 用户编辑 → 保存为今日记录”。

- 录音前明确麦克风权限和最长时长（建议 120 秒）。
- 转写结果先放在编辑框，用户确认保存后才写入 check-in。
- 音频默认不长期保存；转写失败时允许重试，原始音频仅保留短暂上传生命周期。
- Chat 增加“整理成今日记录”提议卡，显示来源消息、拟保存正文和目标日期；仍走现有确认协议。
- 语音和 Chat 生成都不能绕过记忆候选、提议确认和幂等机制。

验收：用户可以在 60 秒内完成一次语音记录；网络中断可重试且不产生重复记录；Chat 未确认前数据库不新增 check-in、记忆或行动。

### P1：记忆上下文控制

先做“全局默认 + 单条记忆控制”，避免一开始建设复杂策略编辑器。

- 全局开关：允许 Today 在 Chat 中使用长期记忆（默认开启，首次使用明确告知）。
- 单条记忆范围：允许用于 Chat、仅保留在时间轴、暂停使用。
- 敏感记忆默认不主动引用，除非用户明确要求；用户可以查看引用来源并撤销。
- 主动跟进单独开关，不因关闭 Chat 记忆而自动改变跟进授权。
- 设置变更立即生效，并记录审计事件。

验收：关闭后新 Chat 请求不会检索或注入被禁用记忆；归档/删除后不可被引用；重新开启后只恢复仍有效的记忆；跨账号无法读取设置。

### P1：隐私、导出与正式试用准备

- 隐私说明：解释记录、语音转写、AI 处理、长期记忆、向量检索、删除和保留期限。
- 数据导出：生成一个异步导出包，包含用户可见的记录、总结、记忆、来源、行动、跟进设置和审计摘要；不包含模型密钥、内部提示词或其他用户数据。
- 删除闭环：删除账号前二次确认，标记业务数据删除并清理媒体、向量和导出任务；失败任务可重试。
- 发布门槛：HTTPS、独立密钥、数据库迁移回滚方案、错误监控、崩溃监控、最小权限和灰度名单。
- 真机验证：Android 真机核心路径；iOS 模拟器和至少一条真机关键路径。

验收：导出内容可解压、可读、与用户页面数据一致；删除后无法通过 Chat、时间轴或向量检索找回；发布构建可回滚。

## 3. 用户流程

### 首次激活

注册 → 权限说明 → 保存第一条文字或语音记录 → 查看总结 → 看到一条可确认建议 → 进入 Today。

### 语音记录

Today 点击麦克风 → 授权 → 录音 → 转写中 → 编辑转写文本 → 保存今日记录 → AI 整理中 → 查看总结和记忆候选。

### Chat 整理记录

Chat 对话 → 点击“整理成今日记录” → 展示来源和预览 → 编辑/改日期 → 确认 → 写入今日记录 → 异步总结。

### 记忆控制

Profile/Timeline → 记忆详情 → 上下文范围 → 选择“可用于 Chat / 仅时间轴 / 暂停使用” → 明确反馈生效时间和影响。

### 导出与删除

Profile → 数据与隐私 → 请求导出或删除 → 二次确认 → 查看任务状态 → 完成后通知；删除任务失败时展示重试，不伪造成功。

## 4. 指标与实验

首轮不做复杂 A/B 测试，先建立基线：

- 激活率：注册后 24 小时内保存首条记录。
- 记录频率：每周有效记录次数。
- AI 价值：总结查看率、建议确认率、确认后行动完成率。
- 习惯形成：D1、D3、D7 留存。
- 负向信号：语音权限拒绝率、转写失败率、记忆暂停/删除率、主动跟进停止率。
- 质量：重复记录率、重复提议率、导出失败率、删除后残留引用数。

建议目标：首条记录完成率 ≥70%，7 日留存先达到 25% 的验证门槛，语音转写成功率 ≥95%，删除后有效引用残留为 0。目标用于判断是否继续投入，不作为上线前虚构的承诺。

## 5. 不做事项

本阶段不做复杂宠物成长、社交、家庭共享、日历/健康集成、插件市场、多模型切换和完整语音对话。先验证核心使用频率、授权理解和数据控制。

## 6. 分阶段排期

1. 第 1 周：指标字典、事件补齐、测试用户协议、隐私文案和语音/记忆控制交互原型。
2. 第 2～3 周：语音转写与 Chat 整理记录。
3. 第 4 周：记忆上下文控制和审计。
4. 第 5 周：导出、删除闭环、监控和发布门槛。
5. 第 6 周：5～10 人 7 天试用、修复阻塞问题、形成继续/调整/停止决策。

进入下一切片的条件：上一切片的验收通过，且没有未处理的隐私、授权或数据一致性问题。

## 8. 权限与状态原则

### 用户可见状态

所有长任务都必须显示“准备中、处理中、成功、失败、已过期”之一，并提供下一步动作。失败状态必须说明是否可以重试、是否会产生费用、原始数据会保留多久。

### 数据授权边界

“保存到时间轴”“保存为长期记忆”“允许 Chat 使用”“允许主动跟进”是四个独立授权，不得用一个总开关代替。用户关闭其中一项时，已有数据不自动删除，除非用户明确选择删除。

### 运营边界

试用期间只看聚合指标和脱敏错误；查看原始内容必须有明确的内部权限、访问理由和审计记录。任何临时人工导出都不能作为正式看板替代方案。

## 9. 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 转写供应商不可用或延迟 | 语音记录无法完成 | 任务可重试，保留文字回退，不阻塞 Today |
| 用户误以为转写自动保存 | 隐私和信任风险 | 转写与保存分两步，保存前明确 CTA |
| 关闭记忆后仍被引用 | 高风险隐私缺陷 | 服务端先过滤权限，再做向量检索，增加反向测试 |
| 删除任务部分失败 | 数据残留 | 分步任务、租约、重试和最终一致性检查 |
| 指标缺失被误判为留存下降 | 错误产品决策 | 客户端事件与服务端业务事实双向对账 |
| 试用用户规模扩大过快 | 成本和支持压力 | 灰度名单、限额、人工暂停开关 |

## 10. 决策记录

已确认的开发基线：

- **语音转写**：本阶段只实现接口、任务状态、客户端录音流程和文字回退，不接入真实转写供应商。
- **隐私默认值**：Chat 默认可以使用有效长期记忆；语音成功转写后立即删除音频。
- **首轮试用**：先只验证内部账号，不开放外部用户。

因此，首轮验收以接口契约、权限边界、任务恢复、删除策略和内部账号流程为主；真实供应商接入和 5～10 位外部用户试用列为下一决策点。
